# Архитектура VibeNotes

## Продукт в одном абзаце

Телефон нужен для того, чтобы быстро записать и ориентироваться в неделе. Тяжёлая работа с файлами и длинным контекстом остаётся на ПК (папка с `agents.md` и Claude Desktop). Поэтому главный экран — чат «Входящие», куда пишется всё подряд. AI раскладывает сообщения на события, задачи и заметки и показывает карточку для подтверждения. Данные лежат в `.md` файлах, которые может читать и ПК.

## Отличия от исходного промпта (и почему)

| Промпт | Решение | Почему |
|---|---|---|
| UX в стиле VS Code и Command Palette | Чат-строка как в ChatGPT | Строка ввода и есть палитра команд, только на естественном языке. Отдельная палитра — лишний второй способ сделать то же самое. |
| «Сначала блокнот, AI потом» | Чат и AI с первого MVP, но всё работает и без AI | Ценность приложения — быстрый ввод через AI. Без ключа чат складывает сообщения во «Входящие.md», а заметки и доски редактируются вручную. |
| RAG с embeddings и MCP | Отложены (этапы 3 и 5) | Для MVP хватает полнотекстового поиска как инструмента агента. Тяжёлый контекст живёт на ПК. |
| Room/SQLite для индексов | Индекс в памяти, чат в JSON, настройки в SharedPreferences | Меньше зависимостей (KSP и Room) и меньше способов сломать сборку. SQLite FTS5 появится вместе с RAG (см. риски). |

## Модули

```
core (Kotlin/JVM, без Android)
├── storage   FileStore: интерфейс файлов хранилища; LocalFileStore (java.io); VaultPaths
├── notes     NotesRepository: инкрементальный индекс, поиск, создание, переименование, корзина
├── kanban    KanbanFormat (формат Obsidian Kanban) · KanbanBoard (чистые операции) · KanbanRepository
├── markdown  Frontmatter, MarkdownText (теги, превью), MarkdownEditing (тулбар, списки),
│             MarkdownBlocks/MarkdownInline (режим просмотра), MarkdownHighlighter (подсветка)
├── ai        LlmClient + OpenAiCompatibleClient (SSE-стриминг, tool calls, отмена, ошибки)
├── agent     AgentTool, ToolRegistry, AssistantEngine (цикл модели), SystemPrompt,
│             ActionProposal + UndoAction, ActionExecutor (выполнение и отмена после подтверждения),
│             AgentOptions (выключенные инструменты, AGENTS.md), DataAccess, ProposalKind
├── calendar  CalendarGateway (интерфейс; чтение, создание, правка, удаление)
├── reminders ReminderSchedule: следующий день/время недельного напоминания (чистая функция)
├── update    UpdateClient: version.json с GitHub, загрузка APK с проверкой SHA-256
├── privacy   AiIgnore (правила .aiignore)
└── inbox     ChatStore (история чата), InboxService (сценарии чата, отмена действий)

app (Android)
├── data      SafFileStore (SAF через DocumentsContract), AndroidCalendarGateway, SecretStore (Keystore),
│             TaskReminder (AlarmManager + уведомление), SettingsRepository
├── AppContainer  ручной DI; Vault — всё, что зависит от выбранной папки
└── ui        Compose-экраны + ViewModel: inbox, notes, editor, kanban, week, settings, onboarding
```

UI, бизнес-логика и сеть разделены: экраны зависят от ViewModel, ViewModel — от сервисов `core`, а сеть живёт только в `OpenAiCompatibleClient`. `core` тестируется на обычной JVM: в этом окружении это дало быстрый цикл проверки без Android SDK.

## Модель рассуждает, система действует

```
сообщение → AssistantEngine ──(tools)──► READ-инструменты: search_notes, read_note, list_tasks,
                │                          list_calendars, list_calendar_events → результат сразу модели
                │
                └──────────────────────► PROPOSE-инструменты: create_calendar_event, update_calendar_event,
                                           delete_calendar_event, add_task, update_task, create_note,
                                           append_to_note → ActionProposal (карточка)
пользователь жмёт «В календарь» → ActionExecutor → CalendarGateway.insert → проверка чтением → статус
«Отменить» → ActionExecutor.undo(UndoAction) → обратная операция → проверка
```

- PROPOSE-инструменты ничего не выполняют. Модели отвечаем: «показано пользователю, не выполнено».
- Аргументы валидируются (`ProposalValidator`). Ошибка уходит обратно модели, а не в карточку.
- Правки и удаления идут так же: модель сначала вызывает `list_calendar_events` / `list_tasks`, получает id события или точное название карточки, затем предлагает `update_calendar_event` / `delete_calendar_event` / `update_task`. Карточка показывает «было → стало».
- После вставки событие перечитывается из Calendar Provider. Успех показывается только если оно там есть. Правка и удаление тоже проверяются чтением.
- `ActionResult.Success` несёт `UndoAction` (id события, путь заметки, текст карточки или снимок «до»). `InboxService.undo` проигрывает обратную операцию; если цель уже изменилась, карточка честно пишет, почему отмена не удалась, и действие остаётся.
- Защита от prompt injection: всё из заметок и календаря оборачивается в `<untrusted_data>`, и закрыть обёртку изнутри нельзя. Системный промпт запрещает исполнять инструкции оттуда. Изменения в любом случае требуют подтверждения.
- Переключатели «Что ассистент может смотреть» (`DataAccess`) выключают группы READ-инструментов: модель их не видит, а вызов выключенного инструмента возвращает ей ошибку.
- «Без подтверждения» — явное правило пользователя по виду действия (`ProposalKind`). Оно проходит через тот же `ActionExecutor` с проверкой результата. Событие без выбранного календаря всё равно ждёт карточку.
- Относительные даты: в промпт добавлена таблица ближайших 14 дней с днями недели (RU и EN). Без неё LLM часто ошибается с «в четверг».

## Напоминания

- «Задачи и заметки → Напоминание о задачах»: включение, день недели и время. Одно уведомление в неделю.
- `TaskReminderScheduler` ставит `AlarmManager.setAndAllowWhileIdle` (без `SCHEDULE_EXACT_ALARM`), `BootReceiver` переставляет будильник после перезагрузки или обновления приложения.
- `TaskReminderReceiver` перечитывает доски, считает просроченное и ближайшее, показывает уведомление. Если открытых задач нет, уведомление не показывается.
- Сервер не участвует; содержимое уведомления считается по локальным `.md`.

## Обновления

```
CI: сборка N (versionCode = номер запуска) → VibeNotes.apk → version.json {versionCode, apkUrl, sha256, notes}
приложение: version.json → новее? → плашка «Обновить» → APK в cache/updates → SHA-256 совпал?
          → в архиве тот же пакет и версия новее? → FileProvider → системный установщик (подтверждает пользователь)
```

- `version.json` выкладывается после APK, поэтому телефон не увидит версию, файла которой ещё нет. Если файл всё же заменили во время загрузки, не совпадёт SHA-256, и установка не начнётся.
- Подпись общая (ключ debug из репозитория), так что Android ставит сборку поверх старой и сохраняет данные. Чужой APK с тем же именем пакета Android не установит из-за другой подписи.
- Разрешение `REQUEST_INSTALL_PACKAGES` нужно только для этого. Android всё равно один раз спрашивает «разрешить установку из VibeNotes» и каждый раз — подтверждение установки.

## Хранение

- Заметка — `Название.md`. Название берётся из имени файла, как в Obsidian.
- Удаление перемещает файл в `.trash/` внутри хранилища, отмена доступна в snackbar.
- Доска — `.md` с frontmatter `kanban-plugin: board`: колонки `## …`, карточки `- [ ] …`, срок `@{yyyy-MM-dd}`, время `@@{HH:mm}`. Неизвестное содержимое (настройки плагина, архив, многострочные карточки) сохраняется байт в байт.
- Каждое изменение доски сначала перечитывает файл, поэтому правки, пришедшие синхронизацией с ПК, не затираются.
- Закрепления, настройки и история чата хранятся в приложении, а не в папке, чтобы не засорять синхронизацию.
- Чат — черновик на сегодня: `AppContainer.clearChatIfNewDay` очищает его при первом открытии нового дня (и при отправке после полуночи). История намеренно не сохраняется; заметки, задачи и события не затрагиваются.

## Навигация

```
Нижние вкладки (листаются свайпом)
├── Входящие (старт) ─► карточка → заметка / доска / событие
├── Неделя            ─► доска
├── Задачи: доска; в заголовке другие доски и «Новая доска»
└── Заметки (закреплённые сверху) ─► папка ─► редактор ─► [[ссылка]] → редактор
Шестерёнка в заголовке вкладки ─► Настройки ─► раздел
```

## Архитектурные риски

1. **Производительность SAF.** `DocumentFile` очень медленный, поэтому используются прямые запросы `DocumentsContract` по одному на папку и кэш id. На тысячах файлов первый запуск всё равно займёт секунды. Следующий шаг — сохранять индекс в SQLite между запусками.
2. **Конфликты синхронизации.** Если один файл одновременно правят телефон и ПК, побеждает последняя запись. Доски перечитываются перед изменением, редактор подхватывает внешние правки, если нет локальных. Полноценного слияния нет.
3. **Ошибки LLM в датах и намерениях.** Смягчаются таблицей дат, валидацией, редактируемой карточкой и обязательным подтверждением.
4. **FTS5 на Android.** Системная SQLite не везде собрана с FTS5. Для RAG понадобится своя сборка SQLite (например, requery/sqlite-android) или FTS4.
5. **Embeddings.** У DeepSeek их нет. RAG потребует отдельного провайдера embeddings. Без него — честный фолбэк на полнотекстовый поиск.
6. **Права на календарь.** При отказе есть кнопка «Через Календарь»: открывается системный экран создания события с заполненными полями.
7. **Сборка.** В облачной среде разработки закрыт Google Maven, поэтому Android-часть проверяется в GitHub Actions.
8. **Время напоминания.** Используется неточный `setAndAllowWhileIdle`, поэтому в режиме экономии уведомление может прийти позже выбранного времени. Это осознанный компромисс: точные будильники требуют отдельного разрешения и усложняют настройку.
9. **Отмена после изменения цели.** Для дописывания, правки и удаления «Отменить» проверяет, что событие/карточка/конец заметки не изменились. Если изменились — операция не выполняется, чтобы не затереть чужую правку.

## Дальнейшие этапы

- **RAG (этап 3):** чанкинг по заголовкам, SQLite FTS + embeddings, гибридный поиск, переиндексация по mtime/size (инкрементальность уже есть в `NotesRepository.refresh`), ответы со ссылками `[[…]]`.
- **MCP (этап 5):** `AgentTool` — точка расширения. Remote MCP по Streamable HTTP превратится в набор `AgentTool`, где READ/PROPOSE задаётся пользователем для каждого инструмента. Stdio-серверы на Android не запускаем.
- **Точные напоминания по времени задачи**, виджет «быстрый ввод», месяц в календарном виде.
